# 모듈 작업 명세 (M0~M3, M11, 챗봇·면접 연동)

**한 세션에 한 모듈**만 한다. 순서대로 진행하고 각 모듈의 AC를 만족하면 `docs/PROGRESS.md`를 갱신한다.
범위 밖(Out)에 있는 것은 구현하지 않는다. `[TBD]`는 설정값 자리만 둔다.
화면은 `docs/design/`(테마 `theme.md`, 경로·메뉴 `ia.md`, 위젯·화면 구성 `screens.md`)를 따른다. 이 문서의 화면 설명보다 design 문서가 우선한다.

## S0. 기본 세팅 (별도 프롬프트로 수행)
`SETUP_PROMPT.md` 참조. 기능은 만들지 않는다.

## M0. 반·계정·접근 범위 (1주차)
**목표**: 로그인과 반 단위 접근 통제, 슈퍼어드민의 반 개설·계정 일괄 발급.
**화면/라우트**
- `/login`: loginId + 비밀번호. 성공 시 `/app`으로. `mustChangePassword=true`면 비밀번호 변경 화면으로 강제 이동.
- `/app`: 역할별 홈으로 리다이렉트 (STUDENT → 본인 반, 담당 반이 1개인 교사 → 그 반, 여러 개 → `/app/overview`).
- `/app/c/[cohortId]/...`: 반 단위 레이아웃. 모든 하위 요청은 `requireCohortAccess`를 거친다.
- 슈퍼어드민 화면(`/app/c/...` 밖, `/app/academy/*`): 반 목록·반 개설, 명부 CSV 업로드, 임시 비밀번호 1회 다운로드, 비밀번호 재설정, 계정 비활성화, 담당 매니저·강사 배정.
**구현 범위**
- 세션: 서버 저장형(`AuthSession`), 쿠키는 httpOnly·SameSite=Lax·**host-only(Domain 미지정)**, 토큰은 sha256 해시로 저장. 로그인 시도 제한(IP·계정당 간단한 카운터).
- 명부 CSV 헤더: `이름,로그인ID,연락처,역할` (역할은 STUDENT/INSTRUCTOR/MANAGER). 검증은 zod, 중복 loginId는 행 단위로 오류 보고.
- 임시 비밀번호는 서버에서 생성해 해시만 저장하고, **발급 응답에서 한 번만** CSV로 내려준다. 업로드 원본은 저장하지 않는다.
**AC**: `permissions.md` §3의 반 간 차단 테스트 통과. 슈퍼어드민이 CSV로 8명 계정을 일괄 발급하고 첫 로그인 때 비밀번호가 강제 변경된다.
**Out**: 소셜 로그인, 이메일 인증, 자체 회원가입, 비밀번호 찾기 메일(재설정은 슈퍼어드민이 처리).

## M3. 출결 (2주차) — M0 다음에 M3를 먼저 한다 (핵심 리스크)
**목표**: 명부 화면에서 예외만 입력하고 잔여 허용 결석일을 계산·표시.
**구현 순서**: ① `compute.ts` + 표 기반 테스트(`attendance.md`) → ② `countTrainingDays`, 훈련일·단위기간 생성 로직(반 개설 시) → ③ 매니저 화면 → ④ 수강생 위젯 → ⑤ 강사 열람 목록.
**화면**
- 매니저 `오늘 출결`: 반 명부가 전원 출석으로 열림, 결석·지각·조퇴·외출 버튼으로 예외 기록, `[오늘 출결 확인 완료]`.
- 매니저 `명부 카운터`: 학생별 결석/지각/조퇴/외출 누계, 환산 결석, 잔여, 등급 표. 행 클릭 시 **드로어**에 일자별 기록.
- 수강생 홈 위젯: 잔여 허용 결석일, 등급, 이번 단위기간 결석·지각·조퇴, 병결·휴가 사용(제한 대비), 최종 반영일. "참고용" 표기.
**AC**: 20명 반의 당일 예외 입력이 한 화면에서 가능. 최종 반영일과 미확인 경고 표시. 초기 이관(opening) 1회 입력으로 첫날부터 잔여가 표시. 변경 이력 기록.
**Out**: 엑셀 업로드, 학원 공식 출결 연동, 알림 발송, 외출 계산 `[TBD]`, 병결·휴가 제한값 `[TBD]`.

## M2. 티켓·결석계 (3주차)
**목표**: 상태 있는 티켓과 결석계 모바일 접수, 증빙 열람.
**구현**: `ticket-state.md`의 전이 함수와 테스트 → 서버 액션 → 수강생 접수 화면(모바일 우선) → 매니저·강사 처리 화면(드로어에 이력·증빙 팝업).
**AC**: 허용되지 않은 전이는 서버에서 거부. 승인된 결석계가 해당 일자 공결 이벤트로 자동 반영. 증빙은 권한 확인 후에만 전달.
**Out**: 푸시·메일 알림, 티켓 우선순위·SLA, 챗봇에서 티켓 자동 생성(M4 연동 시).

## M1. 커리큘럼·과제 (3주차)
**목표**: 반 → 주차 → 수업 트리, 자료와 과제 제출.
**AC**: 강사가 수업에 자료를 3클릭 이내로 등록, 수강생이 3클릭 이내로 자료에 도달, 과제 제출·제출 현황.
**Out**: 북마크·검색(제목·태그 검색은 단순 `contains`로만), 파일 직접 업로드가 필요한 자료는 링크 등록 우선(파일 업로드는 storage 추상화 위에서 후속).

## M11. 역할별 대시보드 (4주차)
**목표**: 수강생·강사·매니저·슈퍼어드민의 홈을 위젯 조합으로 구성. 위젯은 `src/components/widgets/`에서 공유.
- 수강생(모바일 우선): 내 출결 위젯, 내 티켓 상태, 마감 임박 과제, 오늘 수업.
- 강사: 담당 반의 위험·주의 학생, 처리 대기 티켓, 최근 제출.
- 매니저: 반별 요약 카드(위험·주의 인원), 처리 대기 티켓, 오늘 출결 입력 진행.
- 슈퍼어드민: 반 목록과 반별 요약, 계정·명부 관리 진입.
**AC**: 각 역할이 홈 한 화면에서 주 업무를 시작할 수 있고, 상세는 드로어·모달로 열린다 (페이지 이동 최소).
**Out**: 차트 라이브러리 도입(필요하면 먼저 묻는다), 위젯 사용자 설정.

## 챗봇·면접 질문 연동 (5주차 이후)
- 이진호(챗봇), 정명주·최주원(면접 질문)이 독립 서비스로 개발한다. LMS는 **서버에서만** HTTP로 호출한다.
- `USE_AI_MOCK=true`일 때 `src/lib/ai/mock.ts`의 목 응답을 사용한다. 규격은 PRD 5.3·M4·M8을 따른다 (`POST /api/chat` 요청에 `cohortId` 포함, 응답에 `sources`, `grounded`).
- AI 장애가 출결·티켓에 영향을 주지 않도록 타임아웃(챗봇 30초, 면접 60초)과 오류 격리를 둔다.
